# Fresh independent review

Use a new context without inherited conversation. Read the [shared rules](../docs/SUITE_CONTRACT.md), requirements, acceptance, implementation, check commands/results, relevant dependency contracts and prior findings. Exclude plans, conversations, project memory and copies of those materials. If fresh context is unavailable, return INDEPENDENT_REVIEW_NOT_RUN.

1. Inspect the current change against every applicable requirement. Assess observable behavior, coverage gaps, dependency interactions, unintended changes and prior findings. Inspect tests for independent expectations and production code for test-only hooks.
2. Independently run relevant checks, including reproductions for suspected gaps where feasible. Use declared setup, cleanup, pass rules and sampling/thresholds. Record commands, working directory, outcomes and useful output. Keep cleanup errors distinct from primary failures. Required manual judgments name the authority and inspected artifact.
3. Assess remaining evidence where substitutes or impractical checks leave gaps. Missing infrastructure is BLOCKED; a violated behavioral deadline is FAIL. Skipped execution is NOT_RUN or BLOCKED. A passing command alone does not prove requirement coverage. Keep requirements and candidate unchanged; if the candidate changes during review, review the new candidate again.
4. Write a review result using [the results template](../templates/RUN_REPORT.md), omitting inapplicable fields. Give requirement-linked findings, evidence/reproductions and required resolutions; confirm prior findings against the current candidate. Report PASS only with sufficient coverage, successful required checks and zero actionable findings. Otherwise report FAIL/BLOCKED/NOT_RUN and what remains. Return the result path and session/turn references for usage accounting; do not read conversation logs to obtain counters.
