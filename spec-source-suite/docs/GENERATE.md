# Generate — supervise dependent tasks

1. Resolve the selected [bundle](MARKDOWN_BUNDLES.md), target, scope, output and evidence paths. No intent yields NO_PROJECT; missing required inputs yield BLOCKED. Initial work uses new output paths; incremental work uses the selected existing implementation. For reconstruction or cross-target work follow [Regeneration](REGENERATION.md).
2. Validate the ordered tasks plus explicit prerequisites: unique IDs, known references, no cycles. Record final assembled-app scenarios before implementation. Partial selections retain prerequisite requirements; an empty selection is NO_WORK.
3. As each task's prerequisites pass, use [Define](DEFINE.md) in this supervisor context. Retain shared constraints, acceptance decisions and dependency interfaces across tasks. Save that task's complete plan and source-linked acceptance; pass relevant memory paths to subsequent ordinary tasks.
4. Dispatch a fresh implementer with [Implement](IMPLEMENT.md), prepared records and scope. Keep it through repairs; it spawns fresh reviewers. Run tasks serially unless parallel work with coordinated interfaces and ownership was explicitly authorized. Capture supervisor and worker session/turn references as they run for [usage reporting](HELPERS.md#usage-reporting).
5. Accept from actual checks, sufficient requirement coverage and independent review with no actionable findings. Failed or blocked prerequisites keep consumers blocked. Reassess affected downstream results when accepted work changes; use messages and supported waits while maintaining user progress updates.
6. After task acceptance, execute the final scenarios on the actual assembled app, including interactions, real-dependency integration and applicable manual checks. Assembly failure leaves the app incomplete: return defects to the implementer, repeat affected checks/review and rerun final scenarios after repair.
7. Save concise [results](../templates/RUN_REPORT.md), [usage](HELPERS.md#usage-reporting) including blocked work, and useful [memory](PROJECT_MEMORY.md). Report the completed scope, actual checks, unresolved blockers and limitations. Resume from complete records and current evidence; reassess stale or missing results.
