# Define

Read the repository AGENTS.md, [shared contract](../../../docs/SUITE_CONTRACT.md), and [Define](../../../docs/DEFINE.md). Follow D1–D4 as the planner.

Use supplied intent or existing authoritative material to author the [standard Markdown bundle](../../../docs/MARKDOWN_BUNDLES.md). Preserve existing approved source text. Prepare complete plan and source-linked acceptance records using [PLAN.md](../../../templates/PLAN.md) and [ACCEPTANCE.md](../../../templates/ACCEPTANCE.md), and describe requirement-linked verification. Resolve normative gaps before approval.

Route by the deliverable. “Implement the plan” for a documentation plan authorizes document authoring, not the app implementation flow. Complete Define's document gate: validate and persist documents and approval identities. Report outstanding document approvals separately from generation readiness; executable app checks, candidates, implementation review, and generation-run evidence are deferred.

Prepare executable checks and complete the freeze gate only within authorized implementation-handoff scope. Return document paths, baseline/approval references, target and ownership, and the applicable readiness state. Honor existing explicit authorization; document approval alone does not authorize app implementation.
