# Portable native tracing

Files are authoritative. `records.py` manages implementation identity and bindings, `trace_adapters.py` parses native formats, and `usage_report.py` imports metadata and analyzes it. All use Python's standard library on a local POSIX filesystem. `flock` serializes concurrent allocation and manifest/report updates; distributed/network-filesystem locking is outside the contract. Interrupted allocations remain reserved. No legacy migration or v1 compatibility is provided.

## Capture and import

1. Allocate an implementation once: `python spec-source-suite/helpers/records.py allocate todoapp`. Reuse the returned root for resumes/repairs. Save task plan/acceptance there under `tasks/<task-id>/`.
2. Obtain the native session ID, selected turn IDs and exact source path from the harness. Codex uses its rollout JSONL. OpenCode uses `opencode export SESSION_ID > /explicit/path/session.json`; its turn IDs are native user-message IDs. Export each participating child session explicitly. Do not discover unrelated history or include inherited fork history as new work.
3. Add source metadata with `python spec-source-suite/helpers/records.py source IMPLEMENTATION SOURCE.json`, then assignment context with `python spec-source-suite/helpers/records.py bind IMPLEMENTATION BINDING.json`. These operations are idempotent. IDs are immutable; add a new source selection and binding for new turns. A source may select multiple turns; one native session retains one agent-run ID, even across task/role changes. Replacement sessions use distinct agent-run IDs. An unbound selection still contributes measured usage; attribution-dependent tables disclose its omission.
4. At task completion or explicit refresh, run `python spec-source-suite/helpers/usage_report.py IMPLEMENTATION`. It rebuilds `runs/<task>/<agent-run>/trace.jsonl` and `reports/usage.json`, `usage.md`, `timeline.json`. Unbound events use `runs/_unassigned/<native-identity-hash>/`. Keep native files available to rebuild; no copied conversations, tool arguments or outputs enter generated artifacts. Existing failure/check evidence remains intact.

Example source (paths are relative to the implementation root or absolute):

```json
{"id":"worker-turns", "adapter":"codex", "source_version":"codex-rollout-0.167.0", "path":"/explicit/rollout.jsonl", "session_id":"native-thread-id", "turn_ids":["native-turn-id"]}
```

Example binding:

```json
{"id":"assignment-1", "source_id":"worker-turns", "turn_ids":["native-turn-id"], "task_id":"feature", "role":"implementer", "agent_run_id":"worker-1", "agent_name":"Builder", "purpose":"Implement task feature", "requested":{"model":"requested-model", "reasoning_effort":"high"}}
```

Use `orchestration` and `validation` for those activities. Optional `agent_name` and `purpose` are concise workflow context on new bindings (at most 500 characters each); do not rewrite historical bindings. Codex native nickname/path are retained separately. Older assignments display their existing run identity and role/task context when a name or purpose is unavailable. Requested settings are optional workflow metadata and are retained separately from observed native settings. Agents never provide per-call logs or calculate totals. Reference-only native exports can contain sensitive content; generated reports retain identifiers/paths and measurements, not that content.

## Adapter contract and accounting

`read_source(source, path)` returns normalized events and coverage diagnostics. Add a parser and pinned profile to `ADAPTERS`/`SUPPORTED`; no accounting changes are needed. Events carry agent/model/tool kind, native session/turn/event ID, source provenance, available parent/call relations, settings, outcome, timing and canonical usage. Import adds implementation/task/role/run/binding IDs and stable event IDs. Reports group downstream by task, run, role, model, reasoning effort, model plus effort, task plus model/effort, tool and task/tool. Model-only grouping retains measured usage even when effort is unavailable. Model/effort tables contain model measurements; tool tables contain tool observations. Missing fields are null, with omissions disclosed. Native lineage includes separate spawn/fork/continuation edges when available; selecting a parent is not required to retain an edge. Reusing a native session retains that identity and its selected turns rather than inventing a new spawn.

Pinned profiles:

| Profile | Native source and measurement scope | Semantics and limitations |
|---|---|---|
| `codex-rollout-0.167.0` | Codex CLI 0.167.0 rollout; `token_usage_record` by native thread/response ID; function/custom calls by thread/call ID | Input includes cached input, output includes reasoning. Ignore legacy token-count snapshots and turn/thread aggregates. Turn context supplies observed model/effort. Structured command-end events establish failure; plain tool returns establish return, not success. Model duration is unavailable without a start. Native metadata retains spawn and fork parentage. |
| `opencode-export-1.2.27` | OpenCode 1.2.27 session export; `step-finish` part ID when present, otherwise the latest-step message snapshot (partial evidence) | Native input excludes cache read/write, so canonical input adds both; output includes reasoning. Prefer individual step usage; message tokens repeat only the latest step. A successful finished message without step parts supplies a partial latest-step measurement. Failed/unfinished messages without steps are unmeasured (native zeros may be initialization). `variant` is retained but never translated to reasoning effort. Step timings and fork/continuation relationships are absent in this export; tool state carries duration/status and session `parentID` carries spawn parentage. |

Canonical uncached input is input minus cache reads (including cache writes). Canonical total is input plus output, never plus reasoning again. Missing operands stay missing. Deduplicate at native measurement scope; conflicting duplicates fail. Wrapper calls and explicitly parented nested calls are separate counts; absence of parent-call metadata cannot establish that a wrapper had no nested operations. Unknown measurements are excluded from subtotals; an all-unknown subtotal is null. Incomplete evidence prevents complete totals, including affected groups. Source-wide gaps propagate across their assignments; unattributable gaps conservatively prevent completeness where their scope cannot be resolved. Unattributed events remain in overall accounting but are omitted only from the affected grouping. Operation time can overlap; it is not wall-clock, CPU or billed time.

Unsupported profile names fail; a mismatched/missing native version is diagnosed as unverified rather than silently claiming support. Missing files, selected turns, counters, truncated JSONL, unfinished turns and unknown attribution remain visible. Structurally invalid exports fail the import. Report files are atomically replaced individually, not as a multi-file transaction; rerun after an interrupted refresh. Binding history and native inputs remain the recovery sources.

## Viewer and evidence limits

From this repository, run `make trace` to refresh the selected implementation's reports and open the local **Agent trace insights** dashboard. Select **Group by** to compare tasks, agents, models, effort or tools; **Find in this table** filters visible rows. Named assignments show each agent's purpose or recorded role/task context, with native lineage available below. **Open timeline in Perfetto** opens the timing view in another tab. Token tables show measured input, cache reads, uncached input, output and reasoning; tool tables show observed calls, outcomes and measured durations. Partial subtotals, missing attribution and coverage are explicit. The default is `.suite/001_portable_tracing`; use `make trace IMPL=.suite/NNN_name` for another explicit implementation. The reusable command is `python spec-source-suite/helpers/trace_view.py IMPLEMENTATION`.

Repeated invocations rebuild the same artifacts and reuse the same local viewer; they do not allocate implementations or duplicate imported events. The viewer uses loopback port 9001, as required by Perfetto's local-file integration. An unrelated port occupant is left alone and reported. Keep the owning terminal running; `Ctrl+C` stops its server. Reinvoking the command requests the refreshed dashboard in the browser's existing window where supported (tab reuse depends on the browser). If browser launching fails, the command prints the ready-to-open URL. The browser must run on the same machine, with internet access only for the optional Perfetto UI; only the dashboard and generated usage/timeline JSON are served locally. An older viewer must be stopped once before using the upgraded command. This is an on-demand viewer, not a recorder or daemon.

If the browser asks for local-device access, allow it for `ui.perfetto.dev`; otherwise the UI cannot fetch the loopback trace. The command does not change browser permissions. The viewer's health endpoint is separate from Perfetto's reserved `/status` RPC probe.

The Perfetto link loads `reports/timeline.json`. Lanes show agent name and role/task assignments; agent slices show purpose or assignment context. Event details include native identity, tool call relationships, observed model/effort and available token counters. The export uses Chrome Trace metadata (`M`), complete operations (`X`), thread instants (`i`), and spawn flows (`s`/`f`). Complete durations require both observed endpoints; single timestamps are instants, and untimed events remain only in trace/report evidence with timeline omissions. Spawn flows require a native session-creation timestamp and selected parent lane; timestamped creation instants anchor both endpoints without inventing operation durations. Missing relationship timing produces no invented arrow.

The fixture files are **synthetic reductions** of pinned native schemas, not recordings or evidence of live integration. Set `PERFETTO_TRACE_PROCESSOR` to an installed official `trace_processor_shell` when running the test suite to enable the optional real-parser regression (otherwise explicitly skipped). Real capture/import results and Perfetto parser/visual checks belong in the implementation's run evidence and package metadata. OpenCode may have already substituted provider-missing counters with zero internally; exports cannot recover that upstream loss. OpenCode fork exports copy messages under new IDs and omit fork provenance, so select only known new-work turns. A source profile is narrower than support for every release/provider.

Interoperability follows [OpenTelemetry's agent/model/tool and parent/transfer examples](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/non-normative/examples-agent-calls.md); no SDK or collector is required. Viewer format: [Perfetto external trace formats](https://perfetto.dev/docs/getting-started/other-formats). Pinned native contracts: [Codex protocol](https://github.com/openai/codex/blob/rust-v0.167.0/codex-rs/protocol/src/protocol.rs), [OpenCode messages](https://github.com/anomalyco/opencode/blob/v1.2.27/packages/opencode/src/session/message-v2.ts), [OpenCode usage normalization](https://github.com/anomalyco/opencode/blob/v1.2.27/packages/opencode/src/session/index.ts), [OpenCode export](https://github.com/anomalyco/opencode/blob/v1.2.27/packages/opencode/src/cli/cmd/export.ts), [OpenCode processor](https://github.com/anomalyco/opencode/blob/v1.2.27/packages/opencode/src/session/processor.ts). MLflow/Phoenix destinations, recorder plugins, automated runners, costs and mandatory services are outside this implementation.
