# Native trace analysis

`records.py` allocates implementations and resolves tasks. `native_traces.py` collects native files and resolves assignments; `trace_adapters.py` parses measurements; `usage_report.py` accounts for them. The collection boundary is separate so harness discovery never changes token accounting. All use Python's standard library on a local POSIX filesystem. `flock` on the suite directory serializes allocation; each implementation's `.records.lock` serializes its capture/collection/report refresh. Distributed locking is outside the contract. Interrupted allocations remain reserved.

## Capture and collection

1. Allocate once: `python spec-source-suite/helpers/records.py allocate todoapp`. It resolves `CODEX_THREAD_ID` through the native SQLite index under `CODEX_HOME` (default `~/.codex`) and copies the session metadata plus active turn to `native/<session-id>/<turn-id>.jsonl`. Missing telemetry is diagnosed on stderr and does not prevent allocation.
2. Reuse the root for repairs/resumes. `python spec-source-suite/helpers/records.py resolve IMPLEMENTATION TASK` resolves only its immediate `tasks/TASK` and captures the current native turn. Include the structured assignment line defined in [shared record rules](../AGENTS.md#records) in ordinary handoffs. Follow-ups inherit assignments until retagged; prose is never an assignment source.
3. Run `make trace IMPL=IMPLEMENTATION`, or `python spec-source-suite/helpers/usage_report.py IMPLEMENTATION` for reports only. Collection refreshes saved selected turns from the host index, follows selected spawn/follow-up/message dispatches and saves identified descendant turns. Native parent metadata corroborates returned agent paths. Known IDs resolve through the index; workspace and recency never establish inclusion. Native fork history and unrelated turns remain excluded. Returned turn/message IDs or delivered message matches resolve follow-ups; a unique new turn in the dispatch interval can resolve an already proven identity. Multiple possible identities/turns produce coverage diagnostics.
4. Analyze the saved files into `reports/usage.json`, `usage.md` and `timeline.json`. Source versions, session identities, selected turns and stable native agent runs come from their contents. Requested settings come from dispatches; observed settings come from native turn context. No manifest, source/bind commands, normalized run-trace copies, registration step, launch wrapper, hook or recorder is used.

Native records retain their original bytes, including partial active tails. Native host storage stays read-only. Refresh atomically replaces copies and reports individually; it is not a multi-file transaction. Repeated collection deduplicates native measurement identities. When host storage is unavailable, saved files still supply known measurements and assignment evidence, with an explicit offline coverage limitation. Missing tags affect attribution rather than measured totals. Ambiguous identities, missing native versions/measurements, unfinished turns and malformed tails remain diagnosed.

For an existing run, explicitly place the desired native files under `IMPLEMENTATION/native/`; each supplied Codex file selects its own native turns. To restrict scope, supply only native metadata and the intended turn's original records. There is no automatic migration or legacy inventory reader. OpenCode remains supported through saved `opencode export SESSION_ID` JSON files under `native/`: native user-message IDs select turns, structured text-part tags supply assignments, and exports must contain only the intended work. No live OpenCode integration is added. Historical implementation directories remain untouched.

Native files can contain private conversations and tool content. Keep them local and outside HTTP hosting. Derived reports retain identifiers, source paths, measurements and structured assignment descriptions, excluding prompts, arguments and tool outputs. Reviewers/validators use reports and their allowed inputs, not raw conversations.

## Assignment recovery

Some hosts encrypt dispatch arguments and delivered agent messages. The collector cannot read their `SUITE` tags. Recipients' local commentary tags remain readable; plaintext delivered tags are accepted only for their native recipient. Agent paths can also come from native `SubAgentActivity` records matched by session ID.

For existing opaque handoffs, create `IMPLEMENTATION/assignment-annotations.json` using verified task/role records:

```json
{"version":1,"assignments":[{"adapter":"codex","session_id":"SESSION","turn_id":"TURN","task":"01_business_logic","role":"implementer","purpose":"Implement business logic","evidence":["runs/01_business_logic/build/result.md"]}]}
```

Annotations fill only missing assignments for exact selected native turns. They cannot select sessions/turns, replace native tags or change observed settings/counters. Duplicate, conflicting or unselected entries fail refresh. Evidence paths must identify existing files inside the implementation; annotations are explicit assertions, not automatically verified conclusions from file contents. They apply only to the named turn, without inheritance. Reports and the dashboard label their assignment source `annotation`; JSON retains evidence paths. Preserve this file alongside native exports for offline analysis. Annotations and native files are never served by the viewer.

## Adapter contract and accounting

`read_source(source, path)` returns normalized events and coverage diagnostics. Add a parser to `ADAPTERS`; no accounting changes are needed. Events carry agent/model/tool kind, native session/turn/event ID, source provenance, available parent/call relations, settings, outcome, timing and canonical usage. Analysis adds implementation/task/role IDs, native session run IDs and derived assignment IDs and stable event IDs. Reports group downstream by task, run, role, model, reasoning effort, model plus effort, task plus model/effort, tool and task/tool. Model-only grouping retains measured usage even when effort is unavailable. Model/effort tables contain model measurements; tool tables contain tool observations. Missing fields are null, with omissions disclosed. Native lineage includes separate spawn/fork/continuation edges when available; selecting a parent is not required to retain an edge. Reusing a native session retains that identity and its selected turns rather than inventing a new spawn.

Pinned profiles:

| Profile | Native source and measurement scope | Semantics and limitations |
|---|---|---|
| `codex-rollout-0.167.0` | Codex CLI 0.167.0 rollout; `token_usage_record` by native thread/response ID; function/custom calls by thread/call ID | Input includes cached input, output includes reasoning. Ignore legacy token-count snapshots and turn/thread aggregates. Turn context supplies observed model/effort. Structured command-end events establish failure; plain tool returns establish return, not success. Model duration is unavailable without a start. Native metadata retains spawn and fork parentage. |
| `opencode-export-1.2.27` | OpenCode 1.2.27 session export; `step-finish` part ID when present, otherwise the latest-step message snapshot (partial evidence) | Native input excludes cache read/write, so canonical input adds both; output includes reasoning. Prefer individual step usage; message tokens repeat only the latest step. A successful finished message without step parts supplies a partial latest-step measurement. Failed/unfinished messages without steps are unmeasured (native zeros may be initialization). `variant` is retained but never translated to reasoning effort. Step timings and fork/continuation relationships are absent in this export; tool state carries duration/status and session `parentID` carries spawn parentage. |

Canonical uncached input is input minus cache reads (including cache writes). Canonical total is input plus output, never plus reasoning again. Missing operands stay missing. Deduplicate at native measurement scope; conflicting duplicates fail. Wrapper calls and explicitly parented nested calls are separate counts; absence of parent-call metadata cannot establish that a wrapper had no nested operations. Unknown measurements are excluded from subtotals; an all-unknown subtotal is null. Incomplete evidence prevents complete totals, including affected groups. Source-wide gaps propagate across their assignments; unattributable gaps conservatively prevent completeness where their scope cannot be resolved. Unattributed events remain in overall accounting but are omitted only from the affected grouping. Operation time can overlap; it is not wall-clock, CPU or billed time.

Source versions are derived from native metadata; a mismatched/missing version is diagnosed as unverified rather than silently claiming support. Missing files, selected turns, counters, truncated JSONL, unfinished turns and unknown attribution remain visible. Structurally invalid exports fail the import. Report files are atomically replaced individually, not as a multi-file transaction; rerun after an interrupted refresh. Saved native inputs remain the recovery sources.

## Viewer and evidence limits

From this repository, run `make trace IMPL=.suite/NNN_name` to continuously collect native updates, calculate reports and open the local **Agent trace insights** dashboard. The default is `.suite/001_portable_tracing`; pass the intended implementation explicitly. The reusable command is `python spec-source-suite/helpers/trace_view.py IMPLEMENTATION --interval 5`. Set `TRACE_INTERVAL=5` on the Make command to configure the same positive, finite interval in seconds. The foreground viewer collects immediately, then waits that interval after each completed attempt; collection passes never overlap. Repeated commands and additional browser tabs reuse that viewer without starting another collector. Restart the owning viewer to change its interval.

The browser polls the existing page at the configured interval and applies its Python-rendered content, retaining grouping, search text, expanded details and scroll position. Collection and polling each default to five seconds, so changes normally become visible in approximately 5–10 seconds plus processing time. The page shows the last successful collection time and brief refresh or connection errors. A failed refresh or connection keeps the last rendered data and retries on the next cycle; initial collection failures remain command errors. Collection continues while idle until `Ctrl+C`. Reports are rebuilt in full with the existing accounting and individually atomic writes.

Live collection reads Codex logs only for saved selected turns and proven descendants, including newly discovered children. Unrelated turns and later root turns still require explicit capture through allocation, task resolution or supplied native files. OpenCode continues to use supplied exports. Missing measurements remain unavailable, and unfinished evidence does not establish that an agent is currently running.

Select **Group by** to compare tasks, agents, models, effort or tools; **Find in this table** filters visible rows. Assignments show native names, purpose, observed model/effort pairs and lineage. Missing effort stays unavailable; requested settings remain separate in usage JSON. **Open timeline in Perfetto** opens timing in another tab when events are available; empty timelines explain missing evidence. Tool tables show calls, outcomes and measured durations. Coverage and attribution omissions remain visible.

The foreground viewer uses loopback port 9001, as required by Perfetto's local-file integration. An unrelated port occupant is left alone and reported. Keep the owning terminal running; `Ctrl+C` stops collection and HTTP serving. Browser window/tab reuse depends on the browser. If launch fails, the command prints the dashboard URL. Only the dashboard and generated usage/timeline JSON are served: native logs, arbitrary files and directory traversal are outside the HTTP boundary. An older viewer must be stopped once before using the upgraded command. Internet access is needed only for the optional Perfetto UI; collection and analysis remain local.

If the browser asks for local-device access, allow it for `ui.perfetto.dev`; otherwise the UI cannot fetch the loopback trace. The command does not change browser permissions. The viewer's health endpoint is separate from Perfetto's reserved `/status` RPC probe.

The Perfetto link loads the current `reports/timeline.json` as a snapshot on demand. An already-open Perfetto timeline does not live-update; open the link again for newer timing data. Lanes show agent name, role/task assignments and observed model/effort pairs; agent slices show purpose and turn settings. The dashboard's agent table also lists observed pairs, preserving settings changes and marking missing values unavailable rather than inferring requested settings. Event details include native identity, tool call relationships and available token counters. The export uses Chrome Trace metadata (`M`), complete operations (`X`), thread instants (`i`), and spawn flows (`s`/`f`). Complete durations require both observed endpoints; single timestamps are instants, and untimed events remain only in report diagnostics with timeline omissions. Spawn flows require a native session-creation timestamp and selected parent lane; timestamped creation instants anchor both endpoints without inventing operation durations. Missing relationship timing produces no invented arrow.

The fixture files are **synthetic reductions** of pinned native schemas, not recordings or evidence of live integration. Set `PERFETTO_TRACE_PROCESSOR` to an installed official `trace_processor_shell` when running the test suite to enable the optional real-parser regression (otherwise explicitly skipped). Real capture/import results and Perfetto parser/visual checks belong in the implementation's run evidence and package metadata. OpenCode may have already substituted provider-missing counters with zero internally; exports cannot recover that upstream loss. OpenCode fork exports copy messages under new IDs and omit fork provenance, so select only known new-work turns. A source profile is narrower than support for every release/provider.

Interoperability follows [OpenTelemetry's agent/model/tool and parent/transfer examples](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/non-normative/examples-agent-calls.md); no SDK or collector is required. Viewer format: [Perfetto external trace formats](https://perfetto.dev/docs/getting-started/other-formats). Pinned native contracts: [Codex protocol](https://github.com/openai/codex/blob/rust-v0.167.0/codex-rs/protocol/src/protocol.rs), [OpenCode messages](https://github.com/anomalyco/opencode/blob/v1.2.27/packages/opencode/src/session/message-v2.ts), [OpenCode usage normalization](https://github.com/anomalyco/opencode/blob/v1.2.27/packages/opencode/src/session/index.ts), [OpenCode export](https://github.com/anomalyco/opencode/blob/v1.2.27/packages/opencode/src/cli/cmd/export.ts), [OpenCode processor](https://github.com/anomalyco/opencode/blob/v1.2.27/packages/opencode/src/session/processor.ts). MLflow/Phoenix destinations, recorder plugins, automated runners, costs and mandatory services are outside this implementation.
