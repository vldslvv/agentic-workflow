# Simplify the spec-source suite

## Summary

Replace dense procedures with short, actionable lists. Simplify the workflow itself while preserving autonomous execution, meaningful verification, independent review, memory between tasks, and usage statistics.

Make a significant reduction through deletion and consolidation. Report before/after instruction word counts without imposing a numeric target.

## Workflow and documentation

- Keep one short shared-rules list and concise Define, Implement, Generate, and Reviewer routines.
- Merge planning guidance into Define, verifier guidance into Reviewer, and isolation guidance into regeneration. Consolidate review/results templates; remove change proposals and structured receipts.
- Align root instructions, local skills, bundle guidance, and templates. Keep the existing app bundle format and task-record locations.
- Retain a brief, separate assignment and acceptance list for building a future automated runner.

The ordinary workflow becomes:

1. Prepare and save the plan and source-linked acceptance criteria.
2. Implement and run proportionate checks.
3. Spawn a fresh reviewer with requirements, acceptance, implementation, check results, and prior findings. Exclude plans, conversations, and project memory.
4. Reviewer independently inspects the change and runs relevant checks.
5. Repair and repeat checks with a fresh reviewer until no actionable findings remain.
6. Record results, useful memory, and usage statistics.

Generate plans tasks as prerequisites pass, keeps implementers through repairs, and verifies the assembled app before claiming completion. Document-only work ends with validated documents.

Remove mandatory frozen checks, digests, role manifests, exhaustive attempt records, and separate approval receipts. Preserve explicit requirements and approved text. Resolve ordinary details autonomously; report blockers when requirements conflict or required capabilities are unavailable.

## Memory, records, and tooling

- Keep full plans, acceptance criteria, and concise results containing checks, findings, resolutions, and blockers.
- Use the existing project memory index and notes. Read relevant notes, pass their paths to subsequent tasks, and update useful lessons. Require no copies, hashes, prescribed metadata, or validation manifests.
- Keep reviewers and reconstruction workers outside project memory. Reconstruction uses approved inputs in a new workspace, excludes prior implementation/history, preserves required behavior, and reports actual isolation limits.
- Remove role-context, check-execution, and memory-validation helpers and their corresponding tests.
- Preserve existing task/run history. Update links, package inventories, and validation metadata to match the simplified package.

## Usage reporting

Retain the usage helper, its CLI/output compatibility, and its tests.

- Capture execution session/turn references as agents run.
- Produce execution totals and per-role/per-session statistics for tokens and tool calls, including supervisor, implementers, and reviewers.
- Include available cached-input/output breakdowns, source references, and a brief explanation of counting limitations.
- Link the statistics from the concise result record, including blocked runs.
- Report unavailable counters and known subtotals honestly; missing telemetry does not block app acceptance.

Source references serve only to select measurements. Add no hash checks, manifest-review steps, or approval gates.

## Validation and acceptance

- Confirm substantial instruction reduction comes from deletion and consolidation, not relocation.
- Check links, skill entry points, templates, and retained package metadata for consistency.
- Run the retained usage tests covering totals, attribution, deduplication, missing counters, and source-log protection.
- Walk through document authoring, implementation with repairs, dependent tasks carrying memory, unavailable review/check capabilities, assembled-app failure, reconstruction exclusions, and missing telemetry.
- Confirm no removed process obligations survive in entry points or templates.
- Report checks actually performed and remaining limitations; documentation walkthroughs do not establish successful app generation.
