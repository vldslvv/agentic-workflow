# Documentation walkthroughs — 007-agent-role-structure

Method: manually trace the named scenario using only shared AGENTS.md plus the applicable role file at each handoff. Read allowed task artifacts separately. These are instruction inspections, not executed app scenarios or an implemented runner. All twelve traces below were performed against the candidate role documents.

| # | Scenario and traced outcome | Acceptance | Result |
|---|---|---|---|
| 1 | Document-only request enters spec-planner. PLANNER steps 1–4 author/validate documents, source coverage, links and prerequisites, then stop with separate generation readiness. No implementation environment or implementation review is a document gate. Root and acceptance-spec route consistently. | ARS-001, 012, 013 | PASS |
| 2 | Tasks A then B: supervisor validates order and waits for A acceptance. A gets a fresh planner with source/code/contracts/memory, then an implementer with records and planner handle. Supervisor tracks paths/status, not planning discussion or memory content. | ARS-003, 004, 015 | PASS |
| 3 | Reviewer finds a source requirement missing from acceptance: REVIEWER step 1 flags it despite passing listed checks; implementer step 4 returns it to its retained planner; PLANNER step 5 preserves source authority and approved versions. | 4 | Candidate fails initial review: the same implementer repairs it and reruns affected checks/regressions, then starts a new reviewer without inherited context. | 5 | All task results pass but assembled interactions fail: supervisor step 5 starts a fresh validator with original project/task requirements, all acceptances, candidate/check evidence/contracts and prior findings.
