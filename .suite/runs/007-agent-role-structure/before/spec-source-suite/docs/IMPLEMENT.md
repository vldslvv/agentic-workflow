# Implement — one ready task

1. Read the shared rules, full plan/acceptance, normative sources, accepted dependency contracts and selected memory notes. Confirm scope, output paths and evidence destination. Missing required inputs or unaccepted prerequisites block work. For a direct task without records, first use [Define](DEFINE.md).
2. Implement and run requirement-linked checks plus relevant regressions. Add meaningful coverage where needed. Save commands, outcomes and useful failure evidence; record unavailable checks and substitute limits. Inspect the diff for unintended changes.
3. Spawn a fresh reviewer with no inherited conversation (`fork_turns="none"` where supported), using [Reviewer](../prompts/REVIEWER.md). Provide source/acceptance paths, candidate location/revision, check commands/results, dependency contracts, prior findings and an output path. Exclude plans, conversations and project memory, including from forwarded result records. Keep the candidate unchanged during review.
4. Repair actionable findings in this context; rerun affected checks and regressions, then spawn a new fresh reviewer. Add missing checks when they test existing requirements. Resolve ordinary check defects without changing required outcomes; report requirement conflicts or unavailable capabilities as blockers. Continue until review has no actionable findings and acceptance is supported.
5. Check the integrated candidate if integration changed it; behavior changes require renewed review. Save [results](../templates/RUN_REPORT.md), link reviewer evidence and [usage](HELPERS.md#usage-reporting), and maintain useful [memory](PROJECT_MEMORY.md). Return acceptance status, result paths and remaining blockers to the supervisor. Generate still verifies the assembled app.
