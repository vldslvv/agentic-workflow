## Shared, regression and final checks

Required commands in the app directory: `cargo fmt --check`, `cargo check --offline`, `cargo test --offline`, `cargo clippy --offline --all-targets -- -D warnings`, allowing a documented network-enabled equivalent if needed for dependency availability. Public library tests remain passing. Real JSON/process integration is required; mocks do not replace the persistent lifecycle or error checks. Assertions must observe behavior through the binary/API and persisted files, without test-only production hooks or implementation-coupled proof.

Required fresh independent task review checks the unchanged candidate against the source and this acceptance. Final independent assembled-app validation remains required after all scheduled tasks and is not claimed by task 02 acceptance.

## Limits and decisions

Command syntax, help aliases, exit statuses and semantic presentation above clarify the unspecified CLI interface; exact wording is implementation-owned. The source's removal/deletion scenario uses `delete`; no `remove` alias is required. No unavailable required check is known. Concurrent writers and crash/power-loss durability remain outside the accepted business scope. Task 03's PostgreSQL/Docker persistence and every-invocation database health check are deferred to that task, not weakened or preimplemented here.
