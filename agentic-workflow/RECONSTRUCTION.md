# Reconstruction

Read before rebuilding without prior implementation. Porting with prior code is a different claim.

1. Define approved behavior, target, retained assets/data/services and compatibility checks. Retained inputs are not reconstructed outputs. Preserve outcomes, thresholds and fixtures; target-specific invocation may change without weakening them.
2. Use a new workspace and fresh allowed-input contexts for every role, including the Supervisor. Export only approved requirements, acceptance, public contracts/examples, permitted retained inputs and applicable workflow guidance and engineering guidelines.
3. Exclude prior code, build products, repository history, old plans, conversations, caches containing prior code, and all memory/copies. Reject traversal and symlink escapes; keep credentials out of exports and logs. Preserve the source workspace and historical evidence.
4. Replace any worker that read excluded material. New plans and code produced within this reconstruction are allowed for their ordinary roles; independent checks still follow [Checks](CHECKS.md).
5. Inspect exports and report actual separation across filesystem access, parent instructions, session memory, caches, remotes and network. Procedural separation is the default; instructions or a new directory do not enforce isolation.
6. If enforced isolation is required, apply and test controls for the declared boundary, including excluded inputs and reviewer results. Unavailable controls block that requirement.
7. Known prior-code leakage invalidates reconstruction claims; ordinary conformance may be reported separately. Resume only this reconstruction's work and label it resumed.
8. Check retained real dependencies. Report target changes, retained boundaries, controls, limits and observed conformance using [Records](RECORDS.md). Finite checks do not prove universal equivalence or reconstruction reliability.
